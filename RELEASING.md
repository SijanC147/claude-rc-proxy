# Release and Homebrew publishing

The only release entrypoint is `.github/workflows/hextap-release.yml`. It is a
thin caller generated by Hextap Toolkit `v0.1.0` and executes the reusable
workflow at immutable commit
`2d4b4615829f983bb4ea7ff2a4b154fb56fd16ea`. The adjacent `# v0.1.0` comment
is operator-readable provenance; the full commit SHA is the execution
identity. Never replace it with `@main`, a floating major tag, or another
mutable ref.

Exactly one workflow responds to `v*` tag pushes. A tag push selects a full
release. Manual dispatch accepts an existing stable tag and always selects
`homebrew-only` recovery.

## Release invariants

- `origin` (`SijanC147/claude-rc-proxy`) is the only write, PR, tag, and
  release target. `upstream` (`dthinkr/claude-rc-proxy`) remains fetch-only
  with the local push URL `no_push`.
- `.hextap.json` is the source release identity. Its exact bytes are copied to
  `.hextap/tap-registration.json`; the private tap owns the corresponding
  `Projects/claude-rc-proxy.json` and Formula.
- `scripts/hextap-build` is the project-owned adapter. It accepts strict
  normalized stable or prerelease SemVer, builds Darwin/Linux arm64/amd64 with
  `CGO_ENABLED=0`, and injects the exact version and source commit.
- `OP_SERVICE_ACCOUNT_TOKEN` is the only source repository secret. The caller
  maps it explicitly as `op_service_account_token`; `secrets: inherit` is not
  allowed. The reusable workflow exposes it only to the stable Homebrew job,
  which reads `op://CICD/GH_PAT/credential` from 1Password.
- Published releases are immutable. Never replace a tag or asset to repair a
  failed release; fix the source and publish a new version.
- Release checks do not need a local proxy, certificate, listener, or service.
  Do not start, stop, restart, reload, or probe a local proxy as part of this
  workflow.

## Owner-controlled repository setup

The generated `.hextap/SETUP.md` is the canonical checklist for the remaining
owner-controlled GitHub setup. Before releasing, ensure that:

1. `main` is the default branch and immutable releases are enabled.
2. the `OP_SERVICE_ACCOUNT_TOKEN` Actions secret name exists;
3. the reviewed `.hextap/rulesets/main.json` and
   `.hextap/rulesets/release-tags.json` policies are applied; and
4. the private tap registration and Formula are present as a matched pair.

Onboarding and local validation do not mutate GitHub, secrets, rulesets,
releases, or the tap. `brew hextap doctor --online` adds bounded read-only
GitHub checks and never repairs drift.

## Pre-release validation

Run the source and caller checks from an isolated checkout:

```sh
go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
scripts/check-go-format.sh
scripts/test-hextap-build.sh
/bin/bash scripts/test-hextap-build.sh
ruby scripts/test-release-workflow-graph.rb
bash -n scripts/*.sh
shellcheck scripts/*.sh
scripts/check-workflows.sh
brew hextap validate --project .
brew hextap validate --project . --build
brew hextap doctor --project .
```

The default doctor is offline and does not execute the adapter. The explicit
`validate --build` command performs the bounded adapter/archive smoke. Run the
same adapter test with a Bash 5 executable when available; GitHub-hosted Linux
and macOS CI provide the cross-platform gates.

An optional readiness check is read-only:

```sh
brew hextap doctor --project . --online
```

## Full releases

After the release change is merged and CI is green on the exact `main` commit,
create and push an annotated tag to the fork:

```sh
git switch main
git pull --ff-only origin main
git tag -a v0.2.0 -m "claude-rc-proxy v0.2.0"
git push origin v0.2.0
```

Stable tags use `vX.Y.Z`. Prereleases use strict SemVer such as
`v0.2.0-rc.1`. The pinned reusable workflow resolves the tag, validates the
tagged manifest once, runs source quality checks, builds and verifies the
declared archives, publishes an immutable GitHub release, and verifies its
attestations. Prereleases stop after GitHub publication. Stable releases may
continue to Homebrew.

The declared release set is:

```text
claude-rc-proxy-darwin-arm64.tar.gz
claude-rc-proxy-darwin-amd64.tar.gz
claude-rc-proxy-linux-arm64.tar.gz
claude-rc-proxy-linux-amd64.tar.gz
SHA256SUMS
```

Each archive contains `claude-rc-proxy`, `LICENSE`, and `README.md`.

## Direct private-tap publication

Stable Homebrew publication is performed inside the pinned reusable workflow;
the source repository no longer dispatches a separate tap workflow. The
Homebrew job:

1. verifies the immutable source release and downloaded assets;
2. requires the resolved source manifest to be semantically equal to the
   current `Projects/claude-rc-proxy.json` registration;
3. renders or updates only `Formula/claude-rc-proxy.rb` release metadata;
4. pushes a non-force commit directly to private tap `main`, retrying bounded
   non-fast-forward races; and
5. waits for the tap `tests.yml` run attached to that exact commit SHA.

Routine releases do not edit tap registration. A manifest identity change is
an owner-reviewed tap migration: update the registration and Formula together
under tap CI before relying on the new identity.

## Homebrew-only recovery window

If GitHub publication succeeded but the stable Homebrew job did not, dispatch
the managed caller with the existing tag:

```sh
gh workflow run hextap-release.yml \
  --repo SijanC147/claude-rc-proxy \
  --ref main \
  -f tag=v0.2.0
```

There is no mode input: manual dispatch is always `homebrew-only`. Recovery
requires an existing immutable, verified, non-prerelease release. It does not
rebuild or change GitHub assets.

Schema 1 deliberately supports only the current-registration window. The
requested tag's complete manifest, including service caveats, must still equal
the current tap registration. There are no historical registration snapshots
or field exceptions. The existing `v0.1.0` source tag is outside that window
because the current registration contains the later XDG-aware service caveat;
do not recreate or replace that release. Recovery is proven by the next stable
tag whose source manifest matches the current registration.

## XDG-aware Homebrew service configuration

Do not hard-code `~/.homebrew`. Resolve Homebrew's effective per-user
configuration root and create the service directory with private permissions:

```sh
service_config_home="$(brew ruby -e 'print ENV.fetch("HOMEBREW_USER_CONFIG_HOME")')"
install -d -m 700 "$service_config_home/services"
```

Create `$service_config_home/services/claude-rc-proxy.env` with mode `0600`.
The file uses `KEY=value` lines and all path values must be absolute:

```dotenv
CLAUDE_RC_PROXY_CA=/absolute/path/to/combined-ca.pem
CLAUDE_RC_PROXY_TOKEN=<pool-token>
CLAUDE_RC_PROXY_LISTEN=127.0.0.1:9801
```

Run the service only as the intended non-root user and only after reviewing
the local runtime impact. Homebrew service output is below
`$(brew --prefix)/var/log/claude-rc-proxy/launchd.log`. Claude Code must trust
the public mkcert root separately; never point `NODE_EXTRA_CA_CERTS` at the
combined signer containing the private key.

## Remote verification

For a completed release, verify the exact source run, immutable release, asset
attestations, tap commit, and tap CI run. The tap Formula must use the released
Darwin URLs and checksums, and the tap registration must remain equal to the
tagged source manifest. These checks are GitHub-side and do not require or
authorize any local service operation.
